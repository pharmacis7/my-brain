
# Java Core Notes

## 1. Primitive Types and Ranges

| Type      | Size   | Range                                    | Default (fields) |
| --------- | ------ | ---------------------------------------- | ---------------- |
| `byte`    | 8 bit  | -128 to 127                              | `0`              |
| `short`   | 16 bit | -32,768 to 32,767                        | `0`              |
| `int`     | 32 bit | $-2^{31}$ to $2^{31}-1$ (≈ ±2.1 billion) | `0`              |
| `long`    | 64 bit | $-2^{63}$ to $2^{63}-1$ (≈ ±9.2 × 10¹⁸)  | `0L`             |
| `float`   | 32 bit | ~7 significant digits                    | `0.0f`           |
| `double`  | 64 bit | ~15–16 significant digits                | `0.0`            |
| `char`    | 16 bit | 0 to 65,535 (unsigned, a UTF-16 unit)    | `'\u0000'`       |
| `boolean` | —      | `true` / `false`                         | `false`          |

- Fields (inside class but outside methods) get default values. **Local variables (inside method, constructor or code block) don't**: using one before you assign it is a compile error.
- `Integer.MAX_VALUE` = 2,147,483,647 and `Integer.MIN_VALUE` = -2,147,483,648. `Long` has the same constants (`Long.MAX_VALUE`, `Long.MIN_VALUE`).

### Literals
```java
long big = 3_000_000_000L;   // L is needed: without it the literal is an int and too big
float f  = 1.5f;             // without f, 1.5 is a double
int million = 1_000_000;     // underscores only make it easier to read
int hex = 0xFF, bin = 0b1010;
int oct = 010;               // TRAP: a leading 0 means octal, so this is 8
```

### Overflow wraps around silently
```java
int x = Integer.MAX_VALUE;
x + 1                        // -2147483648 (no error!)
Math.abs(Integer.MIN_VALUE)  // still negative: +2^31 does not fit in an int
```
- Use `long` when values can go past about 2 billion: money in paise/cents, timestamps in ms, factorials, products of large numbers.
- Use `Math.addExact`, `Math.multiplyExact` or `Math.toIntExact` to **throw** on overflow instead of silently getting a wrong answer.

**The classic trap: the math is done before the value is widened.**
```java
long a = 1_000_000 * 1_000_000;   // WRONG: int * int overflows first, then becomes long
long b = 1_000_000L * 1_000_000;  // RIGHT: one long operand makes the whole multiply long
```

### Casting
- **Widening** (small to big) is automatic: `byte → short → int → long → float → double`, and `char → int`.
  - `long → float` and `int → float` happen automatically but **can lose precision**.
- **Narrowing** needs a cast and keeps only the low bits (eg. short to byte keep only from LSB to MSB 8 bits thats it):
```java
(byte) 200        // -56
(int) 3.99        // 3 (truncates, does not round)
(int) -3.99       // -3
(int) 1e20        // Integer.MAX_VALUE (clamps to the limit)
(int) Double.NaN  // 0
```

### Numeric promotion
- Arithmetic on `byte`, `short` or `char` always produces an **int**.
```java
byte b = 10;
b = b + 1;     // compile error: the result is an int
b += 1;        // OK: compound assignment casts for you (and can overflow silently)
char c = 'a';
c + 1          // 98 (an int)
(char)(c + 1)  // 'b'
```

### Floating point
```java
0.1 + 0.2 == 0.3     // false (0.30000000000000004)
1.0 / 0              // Infinity
0.0 / 0              // NaN
Double.NaN == Double.NaN  // false! Use Double.isNaN(x)
```
- Never use `float` or `double` for money. Use `long` (smallest unit) or `BigDecimal`.
- Compare doubles with a tolerance: `Math.abs(a - b) < 1e-9`.

### Wrappers (`Integer`, `Long`, ...)
- `Integer` values from -128 to 127 are cached, so `==` *seems* to work for small numbers and then fails for larger ones. **Always compare wrappers with `.equals()`**.
```java
Integer x = 200;
Integer y = 200;

System.out.println(x.equals(y)); // true
System.out.println(x == y);      // typically false only true for number <= 128 approx as they are cached so objects points to same location where number is cached
```
- Unboxing `null` Integer object into a int throws `NullPointerException`: for eg. `Integer n = null; int m = n;`

## 2. `var` (Java 10+)

```java
var count = 10;                    // int
var name = "Asha";                 // String
var list = new ArrayList<String>(); // ArrayList<String>
```
- The compiler infers the type, and it stays **statically typed**. `var` is not dynamic typing.
- **Only for local variables** (including `for` loops and try-with-resources). Not allowed for fields, method parameters or return types.
- It needs an initializer: `var x;` and `var x = null;` are compile errors.
- `var arr = {1, 2};` is an error. Write `var arr = new int[]{1, 2};`.
- TRAP: `var list = new ArrayList<>();` becomes `ArrayList<Object>`.
- TRAP: `var x = 1;` is an `int`, not a `long`. Write `var x = 1L;` if you need a long.
- Use it when the type is obvious from the right-hand side. Avoid it when it hides the type: `var result = service.process();`

## 3. Operators

### Precedence (high to low, simplified)
1. `x++` `x--`
2. `++x` `--x` `+x` `-x` `!` `~` `(cast)`
3. `*` `/` `%`
4. `+` `-`
5. `<<` `>>` `>>>`
6. `<` `>` `<=` `>=` `instanceof`
7. `==` `!=`
8. `&` then `^` then `|`
9. `&&` then `||`
10. `? :`
11. `=` `+=` `-=` ...

When in doubt, add parentheses.
x++ -> first use then increment
++x -> first increment then use

### Increment / decrement
```java
int i = 5;
int a = i++;   // a = 5, i = 6 (use the value, then increment)
int b = ++i;   // i = 7, b = 7 (increment, then use the value)
i = i++;       // TRAP: i does not change
```

### Logical
- `&&` and `||` **short-circuit**: the right side (if left decide result then it do not check the right side) runs only if it's needed.
  `if (s != null && s.length() > 0)` is safe.
- `&` and `|` on booleans evaluate **both sides** every time.
- `^` on booleans is XOR.

### Equality
- On primitives, `==` compares values.
- On objects, `==` checks whether both sides are the **same object**. Use `.equals()` for content.
  `"hi" == new String("hi")` is `false`.

### String concatenation runs left to right
```java
1 + 2 + "a"   // "3a"
"a" + 1 + 2   // "a12"
"a" + (1 + 2) // "a3"
```

### Bitwise and shifts
```java
5 & 3    // 1      5 | 3   // 7      5 ^ 3 // 6      ~5 // -6
1 << 3   // 8 (multiply by 2^3)
-8 >> 1  // -4 (keeps the sign)
-8 >>> 1 // huge positive number (fills with 0; unsigned shift)
1 << 32  // 1 for int! Only the low 5 bits of the shift distance are used (6 bits for long)
```
- Check for even: `(n & 1) == 0`. Check for a power of two: `n > 0 && (n & (n - 1)) == 0`.

### Ternary
```java
String label = age >= 18 ? "adult" : "minor";
```
- TRAP: the result type is promoted. `true ? 1 : 2.0` gives `1.0`. (evaluate both 1 is int and 2.0 is double double has larger size so the result type should be double if int and long then long etc.)

### `instanceof` pattern (Java 16+)
```java
if (obj instanceof String s && !s.isEmpty()) { use(s); }
```

```java
//NEW what we use
Object obj = "hello";
if(obj instanceof String s){
	System.out.println(s.length());
}

//OLD Pattern
Object obj = "hello";
if(obj instanceof String){
	String s = (String)obj;
	System.out.println(s.length());
}
```

## 4. Integer Division and Remainder

```java
7 / 2      // 3 (the fraction is dropped)
-7 / 2     // -3 (truncates toward zero, not -4)
7 / 2.0    // 3.5 (one double operand makes it floating point)
(double) 7 / 2   // 3.5
(double) (7 / 2) // 3.0 (TRAP: the division already happened)
5 / 2 * 2.0      // 4.0 (5 / 2 is evaluated first as an int)
```

- `int / 0` throws `ArithmeticException`. `double / 0` gives `Infinity`.
- `Integer.MIN_VALUE / -1` overflows to `Integer.MIN_VALUE`.

### `%` takes the sign of the left operand (the dividend)
```java
7 % 3    // 1
-7 % 3   // -1 (not 2!)
7 % -3   // 1
```
- `n % 2 == 1` fails for negative odd numbers. Use `n % 2 != 0` for odd number check .
- For results that are always non-negative (array wrap-around, clock math): `Math.floorMod(-7, 3)` is `2`, and `Math.floorDiv(-7, 2)` is `-4`.

### Common patterns
```java
int lastDigit = n % 10;
n /= 10;                              // drop the last digit
int pages = (items + size - 1) / size; // ceiling division for positive numbers
int mid = lo + (hi - lo) / 2;          // safe midpoint: (lo + hi) / 2 can overflow
```

## 5. `Math` Class

| Method | Notes |
|---|---|
| `Math.abs(x)` | `abs(Integer.MIN_VALUE)` is still negative |
| `Math.max(a, b)` / `Math.min(a, b)` | |
| `Math.pow(a, b)` | Returns **double**. `(int) Math.pow(10, 2)` is 100, but avoid it for big ints (precision). |
| `Math.sqrt(x)`, `Math.cbrt(x)` | `sqrt` of a negative number is `NaN` |
| `Math.floor(x)` / `Math.ceil(x)` | Return **double**: `floor(-2.5)` is `-3.0`, `ceil(-2.5)` is `-2.0` |
| `Math.round(x)` | Returns `long` for a double and `int` for a float. Rounds half **up**: `round(2.5)` is 3, `round(-2.5)` is **-2** |
| `Math.rint(x)` | Rounds half to even: `rint(2.5)` is `2.0` |
| `Math.random()` | double in `[0.0, 1.0)` |
| `Math.addExact`, `subtractExact`, `multiplyExact`, `toIntExact` | Throw `ArithmeticException` on overflow |
| `Math.floorDiv`, `Math.floorMod` | Round toward negative infinity |
| `Math.hypot(x, y)` | √(x² + y²) without overflow |
| `Math.signum(x)` | -1.0, 0.0 or 1.0 |
| `Math.clamp(v, min, max)` | Java 21+ |
| `Math.PI`, `Math.E` | Constants |

```java
int dice = (int) (Math.random() * 6) + 1;       // 1..6
double r = Math.round(3.14159 * 100) / 100.0;   // 3.14 (note the 100.0)
```

## 6. `if` / `else`

```java
if (score >= 90) grade = 'A';
else if (score >= 75) grade = 'B';
else grade = 'C';
```
- The condition must be a `boolean`. `if (x = 5)` is a compile error (unlike C).
- Always use braces. Without them, only the next statement belongs to the `if`.
- **Dangling else**: an `else` belongs to the nearest `if`.
- Order `else if` checks from most specific to least specific. The first match wins.
- Prefer **guard clauses** (return early) over deep nesting:
```java
if (user == null) return;
if (!user.isActive()) return;
process(user);
```

## 7. `switch`

### Old switch statement (falls through)
```java
switch (day) {
    case 1:
    case 7:
        type = "Weekend";
        break;          // forgetting break falls into the next case
    default:
        type = "Weekday";
}
```

### Switch expression (Java 14+), the one to use
```java
String type = switch (day) {
    case 1, 7 -> "Weekend";
    case 2, 3, 4, 5, 6 -> "Weekday";
    default -> throw new IllegalArgumentException("Bad day: " + day);
};
```
- `->` **never falls through**, so no `break` is needed.
- Several labels go in one case: `case 1, 7 ->`.
- A switch **expression** returns a value and must be **exhaustive** (cover every case, or have `default`).
- Use `yield` to return a value from a block:
```java
int len = switch (s) {
    case "a" -> 1;
    default -> {
        log(s);
        yield s.length();
    }
};
```
- Allowed types: `byte`, `short`, `char`, `int` (and their wrappers), `String`, `enum`. Java 21+ also allows any type with patterns.
- With an enum, write `case RED ->`, not `case Color.RED ->` (before Java 21).
- A switch over all enum constants is exhaustive without `default`.
- A `null` value throws `NullPointerException`, unless you write `case null` (Java 21+).

### Pattern matching switch (Java 21+)
```java
String describe(Object o) {
    return switch (o) {
        case null -> "null";
        case Integer i when i > 100 -> "big int";
        case Integer i -> "int " + i;
        case String s -> "text " + s;
        default -> "other";
    };
}
```
- `when` adds a guard. Put the more specific cases first.
- With a `sealed` interface, covering every permitted subtype is exhaustive, so no `default` is needed.

## 8. `for` Loop

```java
for (int i = 0; i < n; i++) { ... }
```
- Order: **init** (once), then **check condition**, **body**, **update**, and back to check.
- `i` is visible only inside the loop.
- Several variables: `for (int i = 0, j = n - 1; i < j; i++, j--)` (two pointers).
- Infinite loop: `for (;;) { ... }`
- Off-by-one: arrays run from `0` to `length - 1`, so use `i < arr.length`, not `<=`.
- Backwards: `for (int i = n - 1; i >= 0; i--)`.
- Avoid a `double` as a loop counter: `for (double d = 0; d != 1.0; d += 0.1)` never ends.
- TRAP: `for (byte b = 0; b < 200; b++)` runs forever, because a byte never reaches 200.

### `break` / `continue` / labels
```java
outer:
for (int i = 0; i < n; i++) {
    for (int j = 0; j < m; j++) {
        if (grid[i][j] == target) break outer;  // leaves both loops
        if (grid[i][j] < 0) continue;           // next j
    }
}
```

## 9. Enhanced `for` (for-each)

```java
for (int x : arr) sum += x;
for (String s : list) System.out.println(s);
```
- Works on arrays and anything `Iterable` (List, Set, ...). For a Map: `for (var e : map.entrySet())`.
- `x` is a **copy**. Assigning `x = 0` does **not** change the array.
  It can still change the *contents* of objects: `for (Person p : people) p.setAge(0);` works.
- There's no index. Use a normal `for` when you need the position or several arrays at once.
- Removing from a list inside for-each throws `ConcurrentModificationException`. Use `list.removeIf(...)` or `Iterator.remove()`.
- A `null` array or collection throws `NullPointerException`.

## 10. `while` and `do-while`

```java
while (n > 0) {          // checks first, so it can run 0 times
    sum += n % 10;
    n /= 10;
}

do {                      // runs at least once, then checks
    input = read();
} while (!isValid(input));  // note the semicolon
```
- Use `while` when you don't know the number of iterations ahead of time: reading input, binary search, digit processing.
- Use `for` when you count. Use `do-while` when the body must run once (menus, retry prompts).
- `while (true)` + `break` is fine when the exit condition sits in the middle.
- Make sure something in the body moves toward the exit, or it's an infinite loop.

## 11. Methods

```java
public static int add(int a, int b) {
    return a + b;
}
// [access] [static] returnType name(parameters) { body }
```
- `static` methods belong to the class: `Math.max(...)`. Instance methods need an object: `s.length()`.
- A static method cannot directly use instance fields or methods (there's no `this`).
- **Signature = name + parameter types.** The return type is **not** part of it.

### Overloading
```java
int area(int side)               { ... }
int area(int w, int h)           { ... }
double area(double r)            { ... }
```
- Same name with different parameter lists. Only changing the return type is a compile error.
- The compiler picks the overload in this order: **exact match → widening → boxing → varargs**.
  `void f(long x)` and `void f(Integer x)`: `f(5)` calls the `long` version (widening beats boxing).

### Varargs
```java
int sum(int... nums) { ... }   // nums is an int[]
sum(); sum(1); sum(1, 2, 3);
```
- Only one varargs parameter per method, and it must be the **last** one.

### Recursion
- Every recursive method needs a base case. Very deep recursion throws `StackOverflowError`.

## 12. Parameters: Java is Always Pass-by-Value

```java
void change(int x) { x = 99; }                  // the caller's int does not change

void change(int[] arr) { arr[0] = 99; }          // the caller SEES this (same array)

void change(int[] arr) { arr = new int[]{99}; } // the caller does NOT see this
```
- Primitives: the **value** is copied.
- Objects: the **reference** is copied. You can change the object it points to, but you can't make the caller's variable point somewhere else.
- `String` and the wrappers are immutable, so a method can never change the caller's `String`.
- A method can't swap two of the caller's variables.

## 13. Return Types

- `void` returns nothing. A bare `return;` exits early.
- A non-void method must return a value on **every path**, or the compiler complains:
```java
int sign(int x) {
    if (x > 0) return 1;
    else if (x < 0) return -1;
    return 0;                     // needed
}
```
- Code after a `return` in the same block is unreachable and won't compile.
- Return a value of a compatible type: `return 5;` works from a method returning `long` or `double` (widening).
- Return several values with a `record`: `record MinMax(int min, int max) {}`.
- Prefer returning an empty collection over `null`, and use `Optional<T>` for "maybe no result".
- An overriding method may return a **subtype** of the original return type (covariant return).

## 14. `final`

| Used on              | Meaning                                                            |
| -------------------- | ------------------------------------------------------------------ |
| Local variable       | Can be assigned only once                                          |
| Parameter            | Can't be reassigned inside the method                              |
| Field                | Must be assigned exactly once, by the end of the constructor       |
| `static final` field | A constant: `static final int MAX_USERS = 100;` (UPPER_SNAKE_CASE) |
| Method               | Can't be overridden                                                |
| Class                | Can't be extended (`String`, `Integer`)                            |

```java
final int x;      // a "blank final" is fine
x = 5;            // the first assignment is OK
x = 6;            // compile error

final List<String> names = new ArrayList<>();
names.add("A");   // OK: the LIST can still change
names = new ArrayList<>(); // error: the REFERENCE can't change
```
- **`final` does not make an object immutable.** It only fixes the variable. For an unchangeable list, use `List.of(...)` or `Collections.unmodifiableList(...)`.
- **Effectively final**: a local that is never reassigned counts as final, even without the keyword. Lambdas and inner classes can only use effectively final locals.
- `static final` primitives and Strings set to a literal are **compile-time constants**. The compiler copies them into the code that uses them, and they can be used as `case` labels.
- `final` fields make objects safer to share between threads (they're guaranteed to be visible once the constructor ends).

## Quick Trap Checklist

1. `Integer.MAX_VALUE + 1` is `Integer.MIN_VALUE`. Overflow is silent.
2. `long x = a * b;` with int `a` and `b` overflows before it becomes a long.
3. `010` is 8 (octal).
4. `byte + byte` is an `int`. `b += 1` compiles, but `b = b + 1` doesn't.
5. `0.1 + 0.2 != 0.3`. Don't use doubles for money.
6. Compare objects and wrappers with `.equals()`, not `==`.
7. `i = i++` leaves `i` unchanged.
8. `1 + 2 + "a"` is `"3a"`, but `"a" + 1 + 2` is `"a12"`.
9. `-7 / 2` is `-3` and `-7 % 3` is `-1`. Use `floorDiv` / `floorMod` when you need floor behavior.
10. `(double)(a / b)` is too late. Write `(double) a / b`.
11. `Math.round(-2.5)` is `-2`. `Math.pow` returns a double.
12. An old `switch` without `break` falls through. Use `->`.
13. Assigning the for-each variable doesn't change the array. Removing during for-each throws.
14. Java is pass-by-value, including for object references.
15. A `final` reference can still point to an object that changes.
16. `var list = new ArrayList<>()` is `ArrayList<Object>`.
